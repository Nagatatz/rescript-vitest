# Binding verification

- `pnpm build && pnpm test` runs the compiled ReScript property suite. It enumerates 256 combinations of optional scalar fields and compares the binding to upstream's `mergeConfig`, with independent assertions for override priority and preservation of a non-conflicting value. The unit suite still covers the other bindings.
- CI keeps its lockfile test and checks the newest Vitest 4 on the regular CI triggers. Its weekly and on-demand runs also check the newest Vitest 5; the `test-vitest-4` job identity remains unchanged. An upstream job failure is a compatibility signal, not authorization to publish a new peer range or version.
- `pnpm test:mutation` runs the existing mutator over compiled JavaScript. Compiler-erased type contracts and many FFI mapping changes cannot be covered by that mutator. For this contract's negative control in a disposable checkout, change the binding of `mergeConfig` to `defineConfig`, rebuild, and run `pnpm exec vitest run __tests__/VitestConfig_property_test.res.js`; the property test must fail while compilation still succeeds. Never mutate the working checkout or commit the control.
- In a shell with Elan: `pnpm test:formal`. Lean proves absent overrides preserve the base, present overrides win, and applying a replacement twice is idempotent in the pure scalar option model. This is not a proof of ReScript compilation, JS object merge, Vitest array semantics, or the whole binding. The runtime property bridges two statements of the scalar contract on real compiled source.
